2. DATA LAYER (data/)
--------------------------------------------------------------------------------
• data/authority-policy.json
  - Role: Declarative data representation of Calder County Policy ACA-2026/1 
    and Amendment ACA-2026/2.
  - Contents: Section 2 permitted actions, Section 3.1–3.8 restricted mutation triggers
    (supervisor_escalation), and Section 3.9 minor safeguarding rules (caseworker_handoff).

• data/authority-policy.md
  - Role: Original textual policy document provided in the prompt pack.
  - Contents: Legal specifications and operational limits of caseworker assistants.

• data/referral-queue.json
  - Role: Overnight intake data pack.
  - Contents: 12 intake referrals arriving overnight on 17 March 2026 containing
    referral ID, resident reference, source, summary, and requested actions.


3. MOCK BACKEND SERVICE LAYER (services/)
--------------------------------------------------------------------------------
• services/history_service.py
  - Role: Standard library HTTP microservice running on port 8083.
  - Endpoints:
      GET /residents/<ref>            - Full resident profile, award status, history
      GET /residents/<ref>/household  - Household composition & birthdates
      GET /residents/<ref>/events     - Past case events
      GET /health                     - Service health check
  - Zero external dependencies: Uses built-in http.server.

• services/_history_data.json
  - Role: Mock data store backing history_service.py.
  - Contents: Household demographics, benefit codes, monthly award values, and case event logs.


4. CORE APPLICATION LOGIC (src/)
--------------------------------------------------------------------------------
• src/__init__.py
  - Role: Python package initialization marker.

• src/client.py (ResidentHistoryClient)
  - Role: Safe HTTP transport client.
  - Boundaries: Only implements read operations (GET). Contains no POST/PUT/DELETE
    mutation methods, making out-of-authority writes structurally impossible.
  - Zero external dependencies: Built using urllib.request and json.

• src/guardrail.py (PolicyGuardrailEngine)
  - Role: Deterministic pre-execution policy interceptor.
  - Boundaries: Evaluates referrals against data/authority-policy.json:
      - Intercepts Section 3.1–3.8 restricted actions -> Supervisor Escalation
      - Evaluates household birthdates against 17 March 2026 -> Caseworker Hand-off (Sec 3.9)
      - Falls back to hand-off if household records are missing/unverifiable (Sec 5.2/6.1)
      - Clears adult routine reviews -> Permitted (Sec 2.4)

• src/main.py (run_caseworker_morning)
  - Role: CLI intake orchestrator and execution trace generator.
  - Workflow: Executes the 3-step morning intake loop across all 12 queue items:
      1. Fetch resident record from port 8083 service
      2. Intercept via guardrail engine
      3. Emit Permitted triage drafts, Caseworker Hand-offs, or Supervisor Escalations


5. AUTOMATED TEST SUITE (tests/)
--------------------------------------------------------------------------------
• tests/__init__.py
  - Role: Test package initialization marker.

• tests/test_guardrails.py (TestPolicyGuardrailEngine)
  - Role: Zero-dependency unit test suite using built-in unittest framework.
  - Coverage: Adult-only permitted triage (Sec 2.4), award suspension interception
    (Sec 3.2), bank detail update blocking (Sec 3.4), minor safeguarding hand-offs
    (Sec 3.9), and missing household data fallbacks (Sec 5.2 & 6.1).
